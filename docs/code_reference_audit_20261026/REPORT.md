# code_reference 与当前项目的逐模块功能核查

核查日期：2026-10-26。对照范围为新放入的 `code_reference` 四方案长训练包，以及 `经验小波分解` 当前源码和最近完成的统一数据集任务 1–7。旧 `ViT_reference` 仅用于提供原始波形和分段数组；已通过元信息哈希和新包输入缓存的逐值重建确认其数据对应关系。没有把旧包的 FFT 重采样当作新包的行为。

**结论：两套代码目前并不功能等价。统一数据集的内容、动态窗定位和普通拼接 ViT 结构已经对齐；主要未对齐项是 max1 选帧、插值、投票网络及损失、五折集成、模型选择和训练日程。当前证据能确认功能差异，但不能证明每项差异造成了多少准确率损失。**

本次没有改动训练、预处理源码、数据或历史实验，也没有训练新模型。新增可复跑核查脚本、数值结果、逐样本明细和本报告。

## 1. 数据集差异

### 1.1 最近七组实验的数据内容已一致

实际实验配置均指向 `raw_data_relabeled/统一_cls2_thr1.3`。核查结果：

|检查项|结果|
|---|---|
|train / val / test 数量|161 / 40 / 67|
|各 split 的薄骨 / 厚骨数量|100/61、25/15、41/26|
|样本 ID 与旧参考原始数据的逐行顺序|三组完全一致|
|逐样本厚度、1.3 mm 边界及源标签|完全一致，等于 1.3 mm 属厚骨|
|当前 `load_split` 归零后的 `[268,50,2,896]` 波形|与参考 `source_signal` 逐值相同|
|新包与旧原始数据的 `source_metadata.json`、`split_indices.npz` 哈希|均一致|
|新包四种方法的开发集/测试集 ID 与物理标签|全部一致，开发集顺序按 ID 映射核对|
|用原始信号、参考切片和新包算法重建全部冻结输入|四方法 × 开发/测试共 8 组缓存，所有 main/tail/whole 数组逐值相同，最大误差 0|

所以，对于这七组统一数据集实验，**样本错配、厚度错标、ADC 归零差异不是当前发现的解释**。存储的 `X.npy` 与参考源数组有大量零电平数值差异，这是当前读取入口把 ADC 127/128 归零之前的差异，不能拿存储数组直接比较就认定数据错了。

标签编号相反：当前 0=薄、1=厚；参考模型 0=厚、1=薄。参考是在模型输入时做 `1-source_y`，物理分类任务相同。比较混淆矩阵要同时交换行列，比较概率要用 `p_current(thick)` 对 `1-p_reference(thin)`。一致地置换标签和输出类别不改变交叉熵；数值检查误差为 0。无需为此修改当前标签，但参考权重不能不经类别映射直接评估。

## 2. 预处理差异

### 2.1 max1：最明显的输入差异

参考 peak 方法（`six_channel`、`beam_vote`、`six_channel_beam_vote`）使用：

`f* = argmax_f max_{Beam, 全部896采样点} |x[f,Beam,t]|`

得到一个共享帧号；两个 Beam 的主体、尾部、全段全部使用这一帧。峰值同分按真实 frame ID 排序。

当前 channel3 使用：

`f*_Beam = argmax_f max_{该Beam的动态主体窗} |x[f,Beam,t]|`

两个 Beam 独立选帧；各自选中的帧在该 Beam 的全部区域复用。同分按数组帧序。数据中真实帧 ID 顺序与数组顺序一致，因此本次差异不是帧号偏移或同分顺序造成的。

|split|样本数|两个当前 Beam 选帧不同|两个 Beam 都与参考共享帧一致|Beam1 与参考不同|Beam2 与参考不同|
|---|---:|---:|---:|---:|---:|
|train|161|144|17|47|97|
|val|40|35|5|10|25|
|test|67|54|13|19|35|
|合计|268|233|35|76|157|

即 **233/268=86.94%** 的样本至少一个 Beam 与参考输入帧不同。即使两边都叫 max1，输入也大量不同。不能直接断言共享帧优于独立帧；这是需要优先隔离检验的因素。

代码证据：[当前独立选帧](D:/Ultrasound/骨分层/经验小波分解/emd_pipeline.py:943)、[参考共享峰值选帧](D:/Ultrasound/骨分层/code_reference/methods/six_channel_beam_vote/code_snapshot/experiment_prepare_data.py:236)。

### 2.2 channel4 不等同于 energy_top10

|环节|当前 channel4|参考 energy_top10|
|---|---|---|
|候选|各 Beam 各自主体窗峰值 Top10 的交集|完整 Beam1 的峰值 Top10|

### 2.3 dyn_envelope：本次核验一致

当前定位器使用双通道原始 50 帧，各通道按全段峰值取 Top3，平均有符号波形后计算 Hilbert 包络、平滑和阈值定位，并应用现有人工校正。新参考包训练时直接读取已冻结的分割信号，没有在训练循环重新定位。

本次重算 268 点后：

- **536/536 个通道的主体起点完全一致**，主体长度均为 170。
- 尾部均从主体末端连续取 600 点，越界在右侧补零；536 个通道的补零长度全部一致。
- 参考 main/tail 的全部 50 帧切片已核对为完整源信号的对应索引，补零也一致。
- 双方进入模型的均是有符号波形，包络仅用于确定窗口。
- `dyn_envelope_full` 对应主体、尾部、全段三分区；全段为 896 点。

这些结论限于本批固定样本、默认定位参数和已有人工校正。新包不包含重新生成分段数据的全部上游工具，不能由本次相等推论任意未来数据的定位都相同。但目前没有证据支持把分类差距归因于这 268 点的主体窗位置或尾窗补零。

## 3. 模型、损失与训练差异

### 3.1 普通拼接 ViT 已对齐

逐层核查，两边都使用：每“区域×Beam”独立 Conv1d patch embedding → 固定正弦余弦位置编码 → pre-norm TransformerEncoder（GELU）→ token 均值池化 → LayerNorm → 全分支拼接 → Linear/GELU/Dropout/Linear 分类头。

验证用相同输入及完整映射的权重，参数为任务 1 的 B：patch64、dim96、depth4、heads8、mlp384、dropout0。两模型分别用 seed2023 初始化后，映射参数名所得的全部初始参数和位置编码也逐值相同。在 CPU eval 模式：

|结构|当前参数量|参考参数量|同权重 logits 最大差|
|---|---:|---:|---:|
|4 路拼接|1,852,322|1,852,322|0|
|6 路拼接|2,778,338|2,778,338|0|

这是普通模型计算图没有迁移错误的直接证据。实际训练的权重仍会因输入、划分、精度、随机数和模型选择规则而不同；不能把前向相等理解为历史训练结果应相等。

代码证据：[当前编码器与拼接模型](D:/Ultrasound/骨分层/经验小波分解/vit_model.py:38)、[参考编码器与模型](D:/Ultrasound/骨分层/code_reference/methods/six_channel_beam_vote/code_snapshot/experiment_models.py:13)。

### 3.2 cross-vote 与参考 Beam vote 是不同网络

当前四路：每个区域×Beam 的编码向量直接进入自己的分类头，共 **4 头**；六路则 **6 头**。最终所有分支概率平均。

参考四路：先把同一 Beam 的 `[主体特征, 尾部特征]` 拼接，再由该 Beam 的头分类，共 **2 头**。六路则每 Beam 拼接 `[主体, 尾部, 全段]`，仍为 **2 头**。最后两个 Beam 的概率平均。

因此参考分类头能学习同一 Beam 内跨区域的联合关系；当前每个头只能看到单个区域。差异是信息如何交互，不只是参数量：以 B 参数为例，四路投票当前 1,853,192 参数、参考 1,852,612；六路当前 2,779,788、参考 2,778,628。

目前任务 6/7 是四分支 cross-vote；参考最高 61/67 是六路、两个 Beam 头的模型，两者连输入区域数都不同。

代码证据：[当前逐区域投票](D:/Ultrasound/骨分层/经验小波分解/vit_model.py:106)、[参考按 Beam 融合](D:/Ultrasound/骨分层/code_reference/methods/six_channel_beam_vote/code_snapshot/experiment_models.py:65)。

### 3.3 loss function 确实不同

普通拼接分类：两边实际使用无类别权重、无 label smoothing 的交叉熵。不要误读历史 `configs.py` 中的 `label_smoothing=0.03`；实际冻结训练函数和候选参数使用 0。

投票分类：

|当前 cross-vote|参考 Beam vote|
|---|---|
|`L = -log(mean_j p_j(y))`|`L = mean_b[-log p_b(y)]`|
|先平均概率，再取负对数|每 Beam 分别计算交叉熵，再平均损失|
|j 是 4 或 6 个区域分支|b 是 2 个 Beam 头|

即便先假设头数量及预测完全相同，两种损失也不相等。例如两个头对正确类别概率为 0.9 和 0.1：当前式为 **0.693147**，参考式为 **1.203973**。当前式允许强分支补偿弱分支；参考式会分别惩罚每个 Beam 的错误。这不是 `.mean()` 维度的小差别，而是不同训练目标。

这说明两种投票方法不能视作复现关系；不代表当前目标在数学上错误，也不证明它一定更差。

代码证据：[当前训练损失选择](D:/Ultrasound/骨分层/经验小波分解/run_vit_experiments.py:216)、[当前平均概率取 log](D:/Ultrasound/骨分层/经验小波分解/vit_model.py:136)、[参考 BeamMeanCE](D:/Ultrasound/骨分层/code_reference/methods/six_channel_beam_vote/code_snapshot/controlled_driver.py:129)。

### 3.4 训练和评估协议差异

|模块|当前任务 1–7|参考长训练包|判断|
|---|---|---|---|
|选 epoch|val loss 最小，改善量 >1e−6|val AUC 最大，改善量 >1e−8|高优先级差异|
|训练上限 / patience|40 / 12|120 / 20|改变实际训练时长和余弦周期|
|学习率|从有下限的预热公式升到峰值，再余弦降至 5e−6；warmup 后一轮仍为峰值|warmup 为 `peak×epoch/warmup`；随后余弦降到 0|并非同一 warmup-cosine|
|优化器|AdamW，未显式 fused|AdamW(fused=True)|数值实现不同|
|精度|float32，无 autocast|CUDA BF16 autocast|可能影响训练轨迹|
|batch 随机数|CPU DataLoader，独立 Generator(seed2023)|CUDA 全局 RNG 的 randperm|相同 seed 不保证相同 batch|
|梯度裁剪|global norm 1.0|相同|一致|
|初始化 seed|2023|每折重新 seed2023|种子数相同，不等于模型个数相同|
|预测合并|一个模型|5 折等权概率平均|高优先级差异|
|最终阈值|普通模型固定 0.5；cross-vote argmax|固定 0.5|本批无 reward 干扰；精确概率相等时 tie 规则需按类别映射理解|
|候选|5 份 Top15 去重成 52 套，按当前 val accuracy/loss/ID 选优|每方法从 256 套的初筛测试表现取 Top15，再长训练|候选和选优口径不同|

最近七组结果全部关闭 reward；普通 CLI/GUI 的 reward 默认开关是另一个问题，不是本批七组实验低分的原因。当前 52 套候选自身也继承了参考测试筛选的来源，所以也不宜称作从未接触过该测试集的全新验证协议；但本地搜索阶段确实按固定 val 选优，而不是把 52 套都按 test 排名。

现有历史已经证明选 epoch 的规则不是“写法不同但结果相同”：

|任务|当前实际选中 epoch（val loss）|已运行历史中首次最高 val AUC 的 epoch|
|---|---:|---:|
|1|16|17|
|2|18|16|
|3|33|3|
|4|30|24|
|5|27|29|
|6|22|24|
|7|22|16|

## 5. 建议后续验证顺序

先明确要复现哪一种参考方法；普通拼接和 Beam vote 应分别对照，不把四分支 cross-vote 当作两 Beam 投票。

1. **固定数据与训练评估口径。** 使用已核验的统一点位、固定参数及参考折清单，明确单折与五折平均分别报告；候选不再根据该 test 调整。不要边换模型、边换候选、边比较最优 test。
2. **先建立参考功能基线。** 从包内冻结输入直接训练一个预先固定配置，用参考共享选帧、线性插值、普通拼接或明确的两 Beam 投票及对应损失、AUC 早停与原学习率。冻结输入消除了定位和选帧实现歧义。本次输入重建和普通模型同权重验证已为此完成校验准备。
3. **逐项替换输入因素。** 在同一模型、参数、折和训练实现下，分别比较共享 peak vs 当前独立 max1，再比较线性 vs 三次样条。channel4 与 energy_top10 作为另外两种明确命名的算法比较。
4. **逐项替换投票因素。** 先固定编码器与分支数比较“每区域一头”与“同 Beam 融合两头”；随后固定头结构比较平均概率 NLL 与平均各头 CE，避免把结构和损失效果混在一起。
5. **最后检查训练数值因素。** 分别看 loss/AUC 选模型、40/120 轮和学习率周期、FP32/BF16、batch RNG/优化器实现。涉及多因素时先声明是协议整体复现，不能冒充单因素归因。

优先级依据：选帧已造成 86.94% 样本输入帧不一致；投票网络和目标有明确结构性差异；固定 split 单模型与五折 AUC 选择的实验不在同一口径。主体窗、尾窗和普通编码器已经通过直接核验，暂不需要反复修改这些部分。
